## Purpose

以一次检索任务为标注工作的一级单位，让标注员先选择任务，再在任务内直接浏览带进度状态的全部 Query，并继续对每个查询结果逐条作出判断。

## ADDED Requirements

### Requirement: 标注列表按查询任务组织

系统 SHALL 在标注页首先展示当前数据库的查询任务列表。列表中的查询任务 SHALL 包括批量查询任务和单图查询任务，且 SHALL 展示任务名称、执行状态、Query 数量、已完成 Query 数量和标注进度。索引构建等不产生查询结果的任务 MUST NOT 出现在标注任务列表中。

#### Scenario: 展示批量查询任务

- **WHEN** 当前数据库存在一个包含多个 Query 的批量查询任务
- **THEN** 标注列表将该次查询显示为一个任务
- **AND** 任务行显示其 Query 总数与标注完成数

#### Scenario: 展示单图查询任务

- **WHEN** 当前数据库存在一项有可用结果的单图查询任务
- **THEN** 标注列表将该次查询显示为一个包含一个 Query 的任务

#### Scenario: 排除非查询任务

- **WHEN** 当前数据库存在索引构建任务
- **THEN** 该任务不出现在标注任务列表中

#### Scenario: 查询任务尚无可标注结果

- **WHEN** 查询任务仍在排队、执行失败，或尚未产生任何可读取的 Query 结果
- **THEN** 任务列表仍如实显示其执行状态和零个可标注 Query
- **AND** 该任务的进入标注操作不可用

### Requirement: 从任务列表进入任务标注

系统 SHALL 允许用户从任务列表直接进入所选任务的标注工作台，并 SHALL 提供返回任务列表的明确操作。进入任务时 SHALL 默认选中该任务中第一个未完成 Query；若全部完成，则 SHALL 选中第一个 Query。

#### Scenario: 进入含未完成 Query 的任务

- **WHEN** 用户点击一个含有未标注或部分完成 Query 的任务
- **THEN** 系统进入该任务的标注工作台
- **AND** 默认展示该任务中第一个未完成 Query

#### Scenario: 进入已完成任务

- **WHEN** 用户点击一个所有 Query 均已完成的任务
- **THEN** 系统进入该任务的标注工作台
- **AND** 默认展示任务中的第一个 Query 以便复核或修改标注

#### Scenario: 返回任务列表

- **WHEN** 用户在任务标注工作台点击返回任务列表
- **THEN** 系统返回当前数据库的标注任务列表

### Requirement: 使用数据导航切换 Query

任务标注工作台 SHALL 在固定可见的导航区域内，为任务中的每个 Query 提供可直接点击的导航按钮，允许用户不经过中间 Query 而直接切换。系统 MUST NOT 使用表格行选择，也 MUST NOT 以“上一题”或“下一题”作为 Query 切换方式。

#### Scenario: 查看 Query 数据导航

- **WHEN** 用户进入包含多个 Query 的任务
- **THEN** 数据导航通过按钮同时提供任务内全部可用 Query
- **AND** 每个按钮显示可识别该 Query 的标识或文件名

#### Scenario: 直接切换 Query

- **WHEN** 用户点击数据导航中的另一个 Query 按钮
- **THEN** 工作台直接展示所选 Query 及其查询结果
- **AND** 不要求用户依次经过中间 Query

#### Scenario: 滚动时导航保持可见

- **WHEN** 用户纵向滚动任务标注工作台中的 Query 内容或结果内容
- **THEN** Query 数据导航保持在固定可见位置

#### Scenario: 当前 Query 可识别

- **WHEN** 用户正在查看任务中的一个 Query
- **THEN** 对应导航按钮以区别于其他按钮的选中标记显示

#### Scenario: 移除顺序切换控件

- **WHEN** 用户查看任务标注工作台
- **THEN** 页面不显示“上一题”和“下一题”控件

### Requirement: 数据导航显示实时 Query 状态

系统 SHALL 根据当前结果集内候选的标注情况，为每个 Query 导航按钮显示“未标注”“部分完成”“已完成”或“无候选”状态。不同状态 SHALL 使用不同颜色，并 SHALL 同时使用文字、图标或形状差异提供不依赖颜色的状态线索。每次结果标注后，当前 Query、数据导航和任务进度 SHALL 在同一次交互刷新中保持一致。

#### Scenario: 未开始标注

- **WHEN** Query 有当前结果且没有任何结果被标注
- **THEN** 数据导航按钮显示“未标注”状态及其对应颜色和非颜色线索

#### Scenario: 部分结果已标注

- **WHEN** Query 只有部分当前结果已被标注
- **THEN** 数据导航按钮显示“部分完成”状态及其对应颜色和非颜色线索

#### Scenario: 所有结果已标注

- **WHEN** Query 的全部当前结果均已被标注
- **THEN** 数据导航按钮显示“已完成”状态及其对应颜色和非颜色线索

#### Scenario: Query 没有结果

- **WHEN** Query 的当前结果集为空
- **THEN** 数据导航按钮显示“无候选”状态及其对应颜色和非颜色线索
- **AND** 该 Query 不被计为已完成标注

#### Scenario: 标注后状态更新

- **WHEN** 用户标注当前 Query 的最后一个未标注结果
- **THEN** 数据导航立即将该 Query 显示为“已完成”
- **AND** 任务已完成 Query 数同步增加

### Requirement: 任务内保留逐结果标注

系统 SHALL 在选定 Query 下展示其当前查询结果，并 SHALL 允许用户对每个结果独立标注为命中、未命中或跳过，也 SHALL 保留查看历史候选、修改已有标注和填写备注的能力。结果卡片 SHALL 使用更宽的卡片尺寸在同一横向行内展示且不换行；当结果超出可视宽度时，用户 SHALL 能通过横向滚动浏览。

#### Scenario: 标注多个结果

- **WHEN** 用户在一个 Query 下对不同查询结果分别作出判断
- **THEN** 系统分别保存每个结果的标注
- **AND** 一个结果的标注不覆盖同一 Query 下其他结果的标注

#### Scenario: 横向浏览多个结果

- **WHEN** 当前 Query 的结果卡片总宽度超过结果区域的可视宽度
- **THEN** 所有结果卡片保持在同一横向行内且不换行
- **AND** 用户可以通过左右滑动或横向滚动查看未显示的结果卡片

#### Scenario: 复核已完成 Query

- **WHEN** 用户从数据导航选择一个已完成 Query 并修改某个结果的标注
- **THEN** 系统保存新标注
- **AND** 重新计算并显示该 Query 与任务的标注状态

### Requirement: 无迁移关联既有任务与 Query

系统 MUST 在不修改现有数据库结构、不回填历史记录且不执行数据迁移的前提下，使用查询任务保存的 Query 输入与现有 Query 身份动态建立任务成员关系。现有标注和结果 MUST 保持不变。

#### Scenario: 任务载荷可读取

- **WHEN** 查询任务的载荷包含一个与现有 Query 身份匹配的图像路径
- **THEN** 该 Query 出现在该任务的数据导航中
- **AND** 其既有结果、标注和备注保持不变

#### Scenario: 同一 Query 出现在多个任务载荷

- **WHEN** 同一 Query 图路径被多个查询任务使用
- **THEN** 各任务均可导航到同一现有 Query 记录
- **AND** 各入口显示相同的当前结果与标注状态

#### Scenario: 任务载荷不可用

- **WHEN** 某历史任务的载荷已被清理或无法读取
- **THEN** 系统不推测该任务与 Query 的归属关系
- **AND** 不修改任何标注数据

### Requirement: 无归属 Query 保持可访问

系统 SHALL 将未匹配到任何可读取查询任务载荷的现有 Query 汇总为“未归档查询”，并 SHALL 允许用户像普通任务一样进入、导航和标注这些 Query。

#### Scenario: 打开包含旧数据的标注页

- **WHEN** 当前数据库存在无法匹配到查询任务的 Query
- **THEN** 任务列表显示“未归档查询”分组及其 Query 数量和标注进度

#### Scenario: 标注未归档 Query

- **WHEN** 用户进入“未归档查询”并选择一个 Query
- **THEN** 系统展示其全部当前查询结果
- **AND** 用户可以逐结果完成或修改标注
