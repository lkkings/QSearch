## Context

见 `proposal.md` 的动机。当前查询执行已统一进入全局 `TaskQueue`：批量查询任务的 payload 是 Query 图路径列表，单图查询任务的 payload 是含 `query_image_path` 的对象；检索成功后，结果写入每个数据库自己的 `annotations.db`。标注库以 `(database_name, query_image_path)` 唯一标识 Query，并只保留该 Query 最新的结果集及历史候选，不保存来源 `task_id`。

当前标注页只调用 `get_unlabeled_queries()`，用 session 中的数组下标和底部按钮顺序移动。已完成 Query 会从该数组消失，所以它既不能作为稳定导航，也无法承载任务范围。任务历史清理还会同时移除 task payload，因此设计必须允许任务关联信息不完整，并且不能通过迁移补齐。

Streamlit 版本提供原生按钮、可设置稳定 key 的容器和横向布局。任务选择仍属于一次性动作，适合任务表中的按钮列；Query 导航改用始终可见的状态按钮，候选结果改用不换行的横向轨道。页面继续沿用现有宽屏工作台、键盘标注和缩略图能力。

## Goals / Non-Goals

**Goals:**

- 形成“标注任务列表 → 任务工作台 → Query 数据导航 → 结果标注”的两级信息架构。
- 让任务和 Query 的进度均由现有标注数据实时计算，不缓存会过期的派生状态。
- 在零数据库迁移、零 schema 变化的约束下复用任务 payload 建立成员关系。
- 保持从搜索结果直接进入标注页的现有入口，并把目标 Query 定位到可用任务或未归档分组。
- 保留历史候选开关、备注和快捷键标注行为，并把候选展示改为宽卡片单行横向浏览。

**Non-Goals:**

- 不保存每次重搜的独立结果快照；同一路径在多个任务中仍指向标注库里的同一最新 Query 记录。
- 不恢复已被任务历史清理删除的 task 或 payload。
- 不改变检索执行、候选身份、标注写入、导出格式和数据库 schema。
- 不引入新的前端组件或第三方依赖。

## Decisions

### 1. 运行时构建任务投影，不建立新的持久化关联

新增一个只读的标注任务投影层，输入为：

- 当前数据库的 `batch_search` 与 `interactive_search` 任务；
- 各任务通过既有 `TaskQueue.read_payload()` 读取到的 Query 路径；
- `AnnotationManager.list_queries_by_progress()` 返回的全部 Query 及当前候选聚合计数。

批量 payload 的列表项和单图 payload 的 `query_image_path` 统一规范为路径字符串，再按数据库名和原始路径精确匹配现有 Query 身份。任务内顺序沿用 payload 顺序；重复输入只显示一次。同一 Query 路径若存在于多个任务中，可在多个任务投影中出现，但都引用同一个 `query_id`，因此状态一致。

所有未被任何可读 payload 匹配的 Query 组成一个稳定的虚拟任务 `unassigned`，显示名为“未归档查询”。任务不存在、payload 缺失、JSON 不可读或形状非法时只跳过关联并记录可展示的警告，不修改任何数据库内容。

备选方案是在 `queries` 增加 `task_id` 或新增关联表。它能提供精确归属，但需要 schema 升级与历史回填，直接违反“不需要数据迁移”的约束。按创建时间分桶不可靠，也无法处理并发任务，因此不采用。

### 2. 分离执行状态与标注状态

真实任务保留队列中的执行状态（排队、运行、完成、失败、取消），同时从其当前可用 Query 计算标注汇总：

- `query_count`：成功落入标注库且能由 payload 匹配的 Query 数；
- `completed_count`：当前候选数大于零且全部已标注的 Query 数；
- `annotation_progress`：`completed_count / query_count`，零 Query 时为 0；
- `annotatable`：`query_count > 0`。

任务输入总数和可标注 Query 数分开显示，避免运行中或有失败项的任务把“尚未落库”误报成“未标注”。虚拟任务没有执行状态，只显示“未归档”。

Query 展示状态不直接信任存储的 `queries.status`，而由当前候选聚合计数确定：`total == 0` 为“无候选”，`labeled == 0` 为“未标注”，`labeled < total` 为“部分完成”，否则为“已完成”。这样历史候选不进入分母，并补足现有三值状态无法表达“无候选”的问题。

备选方案是增加第四种数据库状态并更新 CHECK、触发器和视图；这仍需要迁移，故不采用。

### 3. 任务列表保留动作列，Query 导航改用固定状态按钮栏

标注页不再直接进入第一个未完成 Query，而先展示任务数据表。表格使用原生 `st.dataframe` 和 `ButtonColumn` 提供“进入标注”动作；无可用 Query 的行禁用进入语义并只呈现状态。点击后把 `qs_annotation_task_id` 和默认 `qs_annotation_query_id` 写入 session，再重跑页面。

工作台顶部先提供“返回任务列表”和任务摘要，随后使用带稳定 key 的容器渲染 Query 按钮导航。导航容器通过样式设置为 `position: sticky`，在纵向滚动结果内容时保持可见，并通过受控的层级、背景和边界避免遮挡内容。Query 数量超过可视宽度时，按钮栏自身允许横向滚动，不把长任务展开成占用大量纵向空间的多行区域。

每个 Query 使用独立按钮直接写入 `qs_annotation_query_id` 并触发 rerun。按钮标签包含序号或文件名以及状态文字/图标，状态同时映射为稳定的样式类：未标注使用中性灰，部分完成使用琥珀色，已完成使用绿色，无候选使用弱化的红灰色；当前 Query 额外使用边框或选中标记。颜色只作辅助表达，不能取代按钮中的状态文字或图标。完整路径、标注数/总数和命中数放入按钮邻近提示或当前 Query 摘要，避免按钮过宽。

当前 Query 由 ID 而不是数组下标保存。任务投影刷新后若该 ID 不再属于任务，则重新选第一个未完成 Query，否则选第一项。标注触发整页 rerun 后仍保持同一 ID，从而让状态表和任务摘要立刻更新。

备选方案是继续使用可选中 DataFrame 或 `selectbox`。DataFrame 虽适合多列排序，但增加了表格阅读和行选择负担，不能形成直接、固定的状态导航；下拉框则会隐藏其他 Query 的状态。因此采用紧凑的横向按钮栏，并通过自身滚动控制长任务的空间占用。

### 4. 候选结果改为宽卡片单行横向轨道，删除顺序 Query 导航语义

`_render_workbench` 接收任务投影和选中的 `query_id`，候选数据读取、历史开关、查询图锚点、结果标注与备注逻辑保持原样。结果区域使用不换行的横向容器，每个候选卡片设置一致且更大的最小宽度，并由外层容器提供 `overflow-x: auto`；卡片宽度不因结果数量增加而压缩，用户通过触控左右滑动、触控板或横向滚动浏览。底部 `_render_footer` 中的“上一题”“下一题”和“跳至未标注”被移除；快捷键帮助保留，但 Enter 不再绑定下一题。`grid_nav` 只负责候选卡片焦点移动，并在需要时将焦点卡片滚动到可视区域。

从搜索页携带 `annotation_query_id` 进入时，页面先在任务投影中查找包含该 Query 的最新任务；找不到则进入 `unassigned`，并选中目标 Query。该兼容路径不会写 URL 或数据库。

### 5. 测试覆盖按钮状态、固定导航与横向结果布局

任务/Query 聚合、payload 规范化、未归档计算、默认选择和状态文案继续由无 Streamlit 副作用的函数承担并用 pytest 覆盖。UI 测试验证任务列表与工作台分支、无结果禁用、返回操作、Query 按钮点击、当前项标记及“上一题/下一题”消失。渲染断言或样式契约测试验证四种状态均产生对应颜色类和非颜色标签、导航容器具有 sticky 语义、结果容器不换行且可横向滚动、卡片具有增大的最小宽度；已有逐结果标注、历史候选和键盘焦点测试继续作为回归保障。

## Risks / Trade-offs

- **[任务归属不是历史快照]** → 同一路径被多个任务使用时，各任务会看到同一个最新 Query 结果和共享标注。界面不声称保存某次执行的独立结果，任务只作为导航分组。
- **[任务历史被清理后无法关联]** → payload 删除会让对应 Query 落入“未归档查询”；不猜测、不丢失、也不修改标注。
- **[大任务包含大量 Query 按钮]** → 每次页面重跑只读取当前数据库的查询任务并保持线性关联；按钮栏限制在固定高度内横向滚动，只渲染当前 Query 的候选图片。
- **[运行中任务的成员会增长]** → 每次 rerun 重建投影，已落库 Query 会自然加入；以 `query_id` 保持当前选择，避免新增行导致下标漂移。
- **[Sticky 导航可能遮挡内容或受父容器影响]** → 为导航保留明确背景、边界和层级，并通过页面样式测试与实际滚动检查校准顶部偏移。
- **[横向结果会隐藏视口外卡片]** → 保留清晰的横向滚动条或溢出提示，并让键盘焦点移动时同步把目标卡片带入可视区域。

## Migration Plan

无需数据迁移。发布时只部署 Python、样式和测试变更；首次打开标注页即从现有任务队列与标注库动态构建视图。回滚时恢复旧页面代码即可，数据库与任务数据没有发生结构或内容转换。
