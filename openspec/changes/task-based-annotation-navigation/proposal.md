## Why

当前标注页把所有未完成 Query 摊平成一个队列，并依赖“上一题/下一题”顺序切换；用户既看不到一次查询任务包含哪些 Query，也无法从导航中识别每个 Query 的完成状态。需要让标注工作的组织方式与实际检索任务一致，同时保留逐结果标注能力和既有标注数据。

## What Changes

- 将一次批量查询或单图查询视为一个标注任务，在标注页首先展示可标注的查询任务列表。
- 点击任务后进入该任务的标注工作台，展示任务内全部 Query 及任务级标注进度。
- 移除“上一题/下一题”顺序切换，改为固定在工作台可见位置、可直接定位任意 Query 的按钮式数据导航。
- 数据导航按钮通过颜色以及文字或图标区分未标注、部分完成、已完成或无候选状态，并额外突出当前 Query；状态在标注后即时刷新。
- 保留当前 Query 下所有查询结果的逐条命中、未命中、跳过与备注标注能力，同时加宽结果卡片并将其保持在同一横向行内，通过左右滑动浏览。
- 通过既有任务载荷中的 Query 路径与标注库的 Query 唯一身份动态关联任务，不新增数据库字段，不回填数据，也不运行数据迁移。
- 将无法由现存任务载荷归属的既有 Query 汇总到“未归档查询”分组，确保旧数据仍可访问和标注。

## Capabilities

### New Capabilities

- `webui/task-based-annotation-navigation`: 定义以查询任务组织标注列表、在任务内通过固定的状态按钮导航切换 Query、以单行横向滑动浏览结果，以及无迁移兼容既有 Query 的行为。

### Modified Capabilities

无。

## Impact

- 主要影响 `annotation_ui.py`、`annotation_manager.py`、任务查询/载荷读取接口、工作台样式与对应测试。
- 不改变 `annotations.db` 与全局任务队列 schema，不新增第三方依赖，不修改既有标注写入语义。
- 标注页的 Query 切换与结果浏览交互发生变化：底部上一题/下一题控件被任务列表和固定的状态按钮导航替代，结果卡片改为加宽的单行横向滑动布局。
