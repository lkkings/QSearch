### 2. 详情页配置界面改进

**之前**：
- 只显示最近一次索引构建任务的基本信息
- 无法修改配置
- 构建/重建索引使用固定的默认配置

**现在**：

## 配置存储

配置通过任务队列持久化：

```python
# 任务队列字段
{
    "task_id": "...",
    "kind": "index_build",
    "database_name": "dataset_name",
    "num_workers": 4,           # CPU 线程数
    "num_gpus": 0,              # GPU 数量
    "config_yaml": "...",       # 自定义 YAML（可选）
    ...
}
```

- `config_yaml`: 完整配置 YAML 字符串，仅在自定义配置时保存
- 使用默认配置时，`config_yaml` 为 `None`

## 用户体验改进

### 之前的工作流

1. 打开详情页
2. 查看索引状态
3. 点击"建立索引"（使用固定默认配置）
4. 无法调整参数
5. 无法查看历史配置

### 现在的工作流

1. 打开详情页
2. 查看"当前配置"标签（了解历史配置）
3. 切换到"修改配置"标签
4. 调整硬件参数（CPU/GPU）
5. 选择配置模式：
   - 使用默认配置（简单）
   - 或勾选"使用自定义配置"并编辑 YAML（高级）
6. 可选：查看配置预览
7. 点击"建立/重建索引"
8. 配置自动保存到任务队列

## 使用场景

### 场景 1：首次建立索引（默认配置）
- 不勾选"使用自定义配置"
- 适合大多数用户

### 场景 2：使用自定义配置
- 勾选"使用自定义配置"
- 编辑 YAML 配置
- 适合需要调整参数的高级用户

### 场景 3：查看历史配置
- 停留在"查看当前配置"标签
- 了解当前索引的构建参数

### 场景 4：重建索引
- 切换到"修改配置"标签
- 调整配置
- 点击"重建索引"

## 设计理念

### 简洁优于复杂

- 移除了预设配置（conservative/balanced/aggressive）
- 预设增加了选择负担，但大多数用户只需要默认配置
- 高级用户可以直接编辑 YAML，无需预设

### 渐进式复杂度

1. **初级用户**：使用默认配置，无需了解配置细节
2. **高级用户**：勾选自定义配置，完全控制所有参数

### 配置即代码

- 自定义配置直接编辑 YAML
- YAML 是配置的源码，无需额外的 UI 表单
- 可复制、可版本管理、可分享
