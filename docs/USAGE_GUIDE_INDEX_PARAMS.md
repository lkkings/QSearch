## 🎯 使用流程

### 步骤 1：数据库迁移（仅首次需要）

```bash
# 如果你已经安装了旧版本，需要先迁移数据库
uv run python scripts/migrate_queue_schema.py
```

**迁移后输出：**
```
✓ 数据库备份已创建
✓ num_workers 列已添加
✓ num_gpus 列已添加
✓ 迁移成功完成
```

---

### 步骤 2：启动 WebUI

```bash
uv run scripts/start_webui.py
```

**或者：**
```bash
uv run streamlit run src/qsearch/webui/app.py
```

浏览器会自动打开 `http://localhost:8501`

---

### 步骤 3：创建数据集

1. 点击左侧导航栏的 **"数据集"**
2. 点击 **"创建新数据集"** 按钮

---

### 步骤 4：填写基本信息

```
数据集名称：例如 "test_dataset_001"
数据集描述：例如 "测试数据集，包含 1000 张题目图片"
图片目录：例如 "data/test_images"
```

---

### 步骤 5：选择配置预设

**选项：**
- **default** ⭐ - 推荐用于大多数场景
- **fast** ⚡ - 快速原型和测试
- **accurate** 🎯 - 生产环境，高精度需求
- **mobile** 📱 - 移动设备拍摄的图片

**选择建议：**
- 第一次使用？选择 **default**
- 快速验证功能？选择 **fast**
- 生产环境？选择 **accurate**
- 处理手机照片？选择 **mobile**

---

### 步骤 6：配置计算资源

#### CPU 模式（默认）
```
并行进程数：4
GPU 数量：0
```
适合没有 GPU 或数据集较小的场景

#### GPU 模式
```
并行进程数：禁用（自动）
GPU 数量：1 或 2
```
适合有 GPU 且数据集较大的场景

**推荐设置：**
- CPU 核心数 8 核 → 并行数设置为 4-6
- CPU 核心数 16 核 → 并行数设置为 8-12
- 有 1 张 GPU → GPU 数量设置为 1
- 有 2 张 GPU → GPU 数量设置为 2

---

### 步骤 7：高级参数配置（可选）

点击 **"高级参数"** 展开面板

#### 7.1 特征提取参数
```
模型路径：models/chinese-roberta-wwm-ext（默认）
图像尺寸：224（默认）
批处理大小：32（CPU）或 64（GPU）
```

#### 7.2 OCR 引擎配置
```
OCR 引擎：paddleocr（推荐）
检测阈值：0.3（默认）
识别阈值：0.5（默认）
```

#### 7.3 索引构建配置
```
索引类型：根据数据集大小选择
  - < 10k 图片：Flat
  - 10k-100k：IVFFlat
  - > 100k：IVFPQ

聚类中心数：
  - 10k 图片：100-200
  - 50k 图片：200-400
  - 100k+ 图片：400-800
```

#### 7.4 匹配策略配置
```
权重分配（总和必须为 1.0）：
  - 图像权重：0.5
  - OCR 权重：0.4
  - 检测结果权重：0.1

相似度阈值：
  - 图像相似度：0.7
  - OCR 相似度：0.5
  - 检测相似度：0.6
```

---

### 步骤 8：预览和确认

点击 **"预览配置"** 查看最终生成的 YAML 配置

**检查项：**
- [ ] 权重总和是否为 1.0
- [ ] 参数值是否在合理范围内
- [ ] GPU/CPU 配置是否符合硬件情况

---

### 步骤 9：创建数据集

点击 **"创建数据集"** 按钮

系统会：
1. 保存数据集元信息
2. 生成配置 YAML
3. 将索引构建任务加入队列
4. 跳转到任务监控页面

---

### 步骤 10：监控任务

#### 主页监控
- 实时队列状态
- 系统资源使用情况（CPU、GPU、内存）

#### 任务详情
1. 点击左侧 **"任务监控"**
2. 找到刚创建的任务
3. 查看：
   - 任务状态（排队/运行中/已完成/失败）
   - 进度百分比
   - 处理速度
   - 预计剩余时间
   - 实时日志

## 🔧 常见调优场景

### 场景 1：内存不足
**问题**：构建过程中内存占用过高

**解决方案：**
1. 降低并行进程数：8 → 4 → 2
2. 减小批处理大小：128 → 64 → 32
3. 使用 GPU 模式（如果有 GPU）

---

### 场景 2：GPU 显存不足
**问题**：GPU OOM（Out of Memory）

**解决方案：**
1. 减小批处理大小：128 → 64 → 32
2. 降低图像尺寸：384 → 256 → 224
3. 减少 GPU 数量：2 → 1

---

### 场景 3：速度太慢
**问题**：索引构建时间过长

**解决方案：**
1. 使用 GPU 模式
2. 增大批处理大小：32 → 64 → 128
3. 选择 fast 预设
4. 降低图像尺寸：384 → 256 → 224

---

### 场景 4：精度不够
**问题**：搜索结果召回率低

**解决方案：**
1. 选择 accurate 预设
2. 增大图像尺寸：224 → 256 → 384
3. 调整权重：增加 OCR 权重
4. 降低相似度阈值：0.7 → 0.6 → 0.5

## 📈 性能优化建议

### CPU 优化
- 并行数 = CPU 核心数 × 0.5~0.75
- 批处理大小：8-32
- 索引类型：Flat（< 10k）或 IVFFlat（> 10k）

### GPU 优化
- GPU 数量 = 可用 GPU 卡数
- 批处理大小：64-128
- 图像尺寸可适当增大：256 或 384

### 内存优化
- 大数据集使用 IVFPQ 索引
- 降低批处理大小
- 减少并行进程数

### 精度优化
- 使用 accurate 预设
- 图像尺寸设置为 384
- 索引类型使用 Flat 或 HNSW
- 适当降低阈值以提高召回
